## 一、技术原理

### 1.1 核心问题

文档解析是知识库系统的入口环节,需要处理多种格式的文档并转换为统一的Markdown格式:

| 问题维度 | 常见挑战 | StarRing 解决方案 |
|----------|---------|-------------------|
| **格式多样** | PDF/Word/Excel/PPT/图片等多种格式 | 统一解析接口 + 多引擎支持 |
| **OCR质量** | 图片/扫描件识别率低 | 多OCR引擎可选 (RapidOCR/MinerU/PaddleOCR) |
| **表格处理** | 复杂表格解析失败 | Markdown表格转换 + HTML表格兜底 |
| **大文件处理** | 100MB+文件内存溢出 | 流式处理 + 分块解析 |
| **格式保留** | 样式/图片/链接丢失 | Markdown格式 + 图片上传MinIO |

### 1.2 文档解析架构


### 2.1 核心解析流程

代码实现（backend/package/starring/knowledge/parser/unified.py，简化示意）：

```python
async def parse_source_to_markdown(source: str, params: dict | None = None) -> MarkdownParseResult:
    """统一文档解析入口"""
    # 1. 判断来源（本地/MinIO）
    if is_minio_url(source):
        # 下载到临时文件
        temp_path = await download_from_minio(source)
        actual_file_path = temp_path
    else:
        actual_file_path = source
    
    # 2. 根据扩展名选择解析器
    file_ext = Path(actual_file_path).suffix.lower()
    
    if file_ext == ".pdf":
        text = await parse_pdf_async(file_path, params)
    elif file_ext in [".docx", ".pptx", ".xlsx"]:
        text = await _convert_with_docling(file_path, params)
    elif file_ext in [".jpg", ".png"]:
        text = await parse_image_async(file_path, params)
    # ... 其他格式
    
    # 3. 清理临时文件
    if is_minio_url(source):
        os.unlink(actual_file_path)
    
    return MarkdownParseResult(markdown=text, file_ext=file_ext)
```

### 2.2 PDF解析策略

代码实现（backend/package/starring/knowledge/parser/pdf.py，简化示意）：

```python
async def parse_pdf(file, params=None):
    """PDF解析，支持多种OCR方式"""
    ocr_engine, processor_params = _resolve_ocr_engine_params(params)
    
    if ocr_engine == "disable":
        # 纯文本PDF，使用PyPDFLoader
        loader = PyPDFLoader(str(file_path))
        docs = loader.load()
        return "\n\n".join([d.page_content for d in docs])
    else:
        # 扫描件PDF，使用OCR
        return DocumentProcessorFactory.process_file(ocr_engine, file, processor_params)
```

**OCR引擎选择**：

| 引擎 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| **RapidOCR** | 免费、速度快 | 复杂排版效果一般 | 简单文档、批量处理 |
| **MinerU** | 支持复杂排版、表格识别好 | 需要GPU | 学术论文、技术文档 |
| **PaddleOCR** | 开源、支持多语言 | 中等性能 | 通用场景 |
| **DeepSeek OCR** | VLM模型、理解能力强 | 收费、速度慢 | 复杂图表、手写体 |

```python
def _convert_with_docling(file_path: Path, params: dict | None = None) -> str:

    converter = _get_docling_converter()
    result = converter.convert(file_path)
    
    if result.status.name != "SUCCESS":
        raise RuntimeError(f"Docling 转换失败: {result.status}")
    
    doc = result.document
    
    # 处理图片
    if hasattr(doc, "pictures") and doc.pictures:
        for pic in doc.pictures:

                # 上传图片到MinIO
                image_data, mime_type = _parse_data_uri(uri)
                url = _upload_image_to_minio(image_data, filename, bucket, prefix)
                # 替换为URL

```

**Docling优势**：

- 格式保留：保留样式、表格、图片

- Markdown输出：适合后续处理

### 2.4 图片处理与上传

代码实现（backend/package/starring/knowledge/parser/unified.py，简化示意）：

```python
def _upload_image_to_minio(image_data: bytes, filename: str, bucket_name: str, object_prefix: str) -> str:
    """上传图片到MinIO，返回URL"""
    minio_client = get_minio_client()
    minio_client.ensure_bucket_exists(bucket_name)
    
    # 生成唯一文件名
    timestamp = int(time.time() * 1000000)
    object_name = f"{object_prefix}/{timestamp}_{Path(filename).name}"
    
    # 上传
    result = minio_client.upload_file(
        bucket_name=bucket_name,
        object_name=object_name,
        data=image_data,
    )
    
    return result.url  # 返回可访问的URL
```

**图片处理流程**：
1. 从Docling输出中提取data URI
2. 解码Base64数据
3. 上传到MinIO（公开bucket）
4. 替换Markdown中的图片标记为URL

```python
async def parse_large_pdf(file_path: str, chunk_size: int = 10) -> str:
    """分块解析大PDF"""
    chunks = []
    for page_num in range(0, total_pages, chunk_size):
        # 仅加载部分页面
        pages = load_pages(file_path, start=page_num, end=page_num+chunk_size)
        text = extract_text_from_pages(pages)
        chunks.append(text)
        # 释放内存
        del pages
    
    return "\n\n".join(chunks)
```

```python
# 转换为Markdown表格
def table_to_markdown(table_data: list[list[str]]) -> str:
    if not table_data:
        return ""
    
    header = table_data[0]
    rows = table_data[1:]
    
    # Markdown表格格式
    md = f"| {' | '.join(header)} |\n"
    md += f"| {' | '.join(['---'] * len(header))} |\n"
    
    for row in rows:
        md += f"| {' | '.join(row)} |\n"
    
    return md
```

### 优化2：异步并发解析

```python
async def batch_parse_files(file_paths: list[str]) -> list[str]:
    """批量异步解析"""
    tasks = [parse_source_to_markdown(path) for path in file_paths]
    results = await asyncio.gather(*tasks, return_exceptions=True)
    
    # 处理异常
    parsed = []
    for result in results:
        if isinstance(result, Exception):
            logger.error(f"解析失败: {result}")
            parsed.append("")
        else:
            parsed.append(result.markdown)
    
    return parsed
```

**效果**：批量解析吞吐提升 5倍（估算）

### 面试要点

**Q: 为什么选择Docling而不是其他库？**
A: Docling是IBM开源项目，官方维护活跃。优势是支持DOCX/XLSX/PPTX统一接口，
格式保留好（样式、表格、图片），直接输出Markdown。相比python-docx只能提取文本，
Docling保留了完整结构。但依赖较重（1GB+），所以我们设计了降级方案，
Docling失败时回退到轻量库。

**Q: 如何处理100MB+大文件？**
A: 我们采用三层策略：1）流式处理，不一次性加载整个文件；2）分块解析，
每10页一批处理；3）内存监控，超过阈值时主动释放。通过这三层保护，
即使500MB的PDF也能稳定处理，内存占用控制在2GB以内。
