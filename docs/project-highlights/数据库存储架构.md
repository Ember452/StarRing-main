# StarRing 数据库存储架构

> **文档版本**: v1.0  
> **更新日期**: 2026-07-24  
> **适用版本**: StarRing 智能体平台

---

## 一、存储架构总览

StarRing 采用**多存储协同架构**，根据数据特性选择最合适的存储引擎：

| 存储引擎 | 存储内容 | 核心用途 |
|---------|---------|---------|
| **PostgreSQL** | 业务数据、元数据、关系数据 | 用户、对话、知识库元数据、图谱元数据 |
| **Milvus** | 向量数据、稀疏向量 | 语义检索、BM25全文检索 |
| **Neo4j** | 知识图谱（实体+关系） | 图谱增强检索、关系推理 |
| **MinIO** | 文件对象 | 原始文档、解析后的Markdown、图片 |
| **Redis** | 缓存、事件流、任务队列 | 实时事件推送、异步任务、会话状态 |

## 二、PostgreSQL 存储详解

PostgreSQL 是系统的**核心关系型数据库**，存储所有业务数据和元数据。

### 2.1 业务数据表（models_business.py）

#### 2.1.1 用户与权限相关

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `departments` | 部门信息 | id, name, description, created_at |
| `users` | 用户账户 | id, username, uid, phone_number, avatar, password_hash, role, department_id, login_failed_count, login_locked_until, is_deleted |
| `api_keys` | API密钥管理 | id, key_hash, key_prefix, name, user_id, department_id, expires_at, is_enabled, last_used_at |
| `agent_envs` | 用户级Agent沙盒环境变量 | id, uid, env(JSON), created_at, updated_at |

**设计亮点**：
- 用户支持**登录失败锁定**（5次失败后锁定300秒）
- 支持**软删除**（is_deleted + deleted_at）
- API Key 支持**过期时间**和**使用追踪**

#### 2.1.2 智能体相关

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `agents` | 智能体定义 | id, slug, backend_id, name, description, icon, pics, config_json, share_config, is_default, is_subagent, created_by |
| `skills` | 技能元数据 | id, slug, name, description, source_type, tool_dependencies, mcp_dependencies, skill_dependencies, dir_path, version, content_hash, enabled |
| `mcp_servers` | MCP服务器配置 | id, slug, name, description, transport, url, command, args, env, headers, timeout, enabled, disabled_tools |
| `model_providers` | 模型供应商配置 | id, provider_id, display_name, provider_type, base_url, api_key, capabilities, enabled_models, is_enabled, is_builtin |

**设计亮点**：
- Agent 支持**多后端**（backend_id 指向具体实现）
- Skill 支持**依赖声明**（工具、MCP、其他Skill）
- MCP Server 支持**三种传输协议**（sse/streamable_http/stdio）

#### 2.1.3 对话与消息

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `conversations` | 对话会话 | id, thread_id, uid, agent_id, title, status, is_pinned, extra_metadata |
| `messages` | 消息内容 | id, conversation_id, role, content, message_type, token_count, extra_metadata, image_content, run_id, request_id, delivery_status |
| `tool_calls` | 工具调用记录 | id, message_id, langgraph_tool_call_id, tool_name, tool_input, tool_output, status, error_message |
| `conversation_stats` | 对话统计 | id, conversation_id, message_count, total_tokens, model_used, user_feedback |
| `message_feedbacks` | 消息反馈 | id, message_id, uid, rating, reason |

**设计亮点**：
- 消息支持**多模态**（image_content 存储Base64图片）
- 工具调用**独立存储**，便于追踪和调试
- 支持**消息反馈**（点赞/点踩）

#### 2.1.4 运行任务与触发器

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `agent_runs` | Agent运行任务 | id, thread_id, agent_id, uid, status, request_id, run_type, input_payload, error_type, error_message, started_at, finished_at |
| `tasks` | 异步任务记录 | id, name, type, status, progress, message, payload, result, error, cancel_requested |
| `triggers` | 触发器配置 | id, name, desc, trigger_type, agent_id, uid, config, input_query, is_active, last_run_at, last_run_status, run_count |
| `workflows` | 工作流定义 | id, name, desc, slug, owner_uid, definition(JSON), version, is_active |
| `operation_logs` | 操作日志 | id, user_id, operation, details, ip_address, timestamp |
| `cli_auth_sessions` | CLI浏览器授权会话 | id, device_code_hash, user_code, status, key_name, approved_user_id, api_key_id, expires_at |

**设计亮点**：
- AgentRun 支持**幂等性**（request_id 唯一约束）
- 支持**中断恢复**（parent_run_id 关联父任务）
- 触发器支持**cron定时**和**webhook**两种类型

### 2.2 知识库数据表（models_knowledge.py）

#### 2.2.1 知识库基础信息

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `knowledge_bases` | 知识库定义 | id, kb_id, name, description, kb_type, embedding_model_spec, llm_model_spec, query_params, additional_params, share_config, mindmap, sample_questions |

**设计亮点**：
- 知识库支持**多种类型**（kb_type: milvus/dify/notion等）
- 存储**查询参数配置**（query_params JSON）
- 支持**思维导图**（mindmap JSON）

#### 2.2.2 文件与分块

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `knowledge_files` | 知识文件记录 | id, file_id, kb_id, parent_id, filename, file_type, path, minio_url, markdown_file, status, content_hash, file_size, chunk_count, token_count, processing_params, is_folder |
| `knowledge_chunks` | 知识分块 | id, chunk_id, file_id, kb_id, chunk_index, content, start_char_pos, end_char_pos, graph_indexed, ent_ids, tags, extraction_result |

**设计亮点**：
- 文件支持**层级结构**（parent_id 自引用）
- 分块记录**字符位置**和**token位置**，便于溯源
- 支持**图谱索引标记**（graph_indexed）

#### 2.2.3 知识图谱元数据

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `knowledge_graph_entities` | 图谱实体 | id, entity_id, kb_id, normalized_name, label, name, attributes |
| `knowledge_graph_entity_mentions` | 实体提及 | id, entity_id, kb_id, file_id, chunk_id |
| `knowledge_graph_triples` | 三元组 | id, triple_id, kb_id, source_entity_id, target_entity_id, relation_type, content |
| `knowledge_graph_triple_mentions` | 三元组提及 | id, triple_id, kb_id, file_id, chunk_id, text, extractor_type |

**设计亮点**：
- 实体支持**归一化名称**（normalized_name），避免重复
- 三元组记录**原文内容**（content），便于验证
- 支持**提及追踪**（mention），知道实体/关系来自哪个chunk

#### 2.2.4 评估系统

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `evaluation_datasets` | 评估数据集 | id, dataset_id, kb_id, name, description, item_count, has_gold_chunks, has_gold_answers, build_metadata |
| `evaluation_dataset_items` | 评估题目 | id, item_id, dataset_id, kb_id, item_index, query_text, gold_chunk_ids, gold_answer |
| `evaluation_runs` | 评估运行 | id, run_id, name, kb_id, dataset_id, status, retrieval_config, metrics, overall_score, total_items, completed_items |
| `evaluation_run_items` | 评估结果 | id, run_id, dataset_item_id, item_index, query_text, generated_answer, retrieved_chunks, metrics |

**设计亮点**：
- 支持**标准答案**（gold_answer）和**标准分块**（gold_chunk_ids）
- 评估结果记录**检索到的chunks**，便于分析检索质量

## 三、Milvus 向量数据库存储详解

Milvus 负责存储**向量化数据**，支持高效的语义检索和全文检索。

### 3.1 Collection Schema

每个知识库对应一个 Milvus Collection，命名规则：`kb_{kb_id}`

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| `id` | VARCHAR(100) | 主键，chunk的唯一标识 |
| `content` | VARCHAR(65535) | 分块文本内容，启用中文分词器 |
| `chunk_id` | VARCHAR(100) | 关联PostgreSQL中的chunk_id |
| `file_id` | VARCHAR(100) | 关联的文件ID |
| `chunk_index` | INT64 | 分块在文件中的序号 |
| `embedding` | FLOAT_VECTOR(dim) | 稠密向量（维度由Embedding模型决定，如1024） |
| `content_sparse` | SPARSE_FLOAT_VECTOR | 稀疏向量（BM25自动生成） |

### 3.2 索引配置

| 索引类型 | 字段 | 配置 |
|---------|------|------|
| IVF_FLAT | embedding | metric_type=COSINE, nlist=1024 |
| SPARSE_INVERTED_INDEX | content_sparse | metric_type=BM25, inverted_index_algo=DAAT_MAXSCORE |

### 3.3 BM25 全文检索

通过 Milvus 内置的 BM25 Function 实现：

```python
bm25_function = Function(
    name="content_bm25",
    input_field_names=["content"],
    output_field_names=["content_sparse"],
    function_type=FunctionType.BM25,
)
```

**设计亮点**：
- **混合检索**：支持向量检索 + BM25 全文检索的加权融合
- **自动稀疏向量**：BM25 Function 自动生成稀疏向量，无需手动计算
- **中文分词**：content 字段启用中文分析器（`enable_analyzer=True`）

## 四、Neo4j 图数据库存储详解

Neo4j 负责存储**知识图谱**，支持实体关系的图结构查询。

### 4.1 节点类型

| 节点标签 | 属性 | 说明 |
|---------|------|------|
| `Entity` | entity_id, kb_id, name, label, attributes | 知识图谱实体 |

**标签规则**：
- 每个知识库的实体使用独立的标签：`Entity:MilvusKB:{kb_id}`
- 标签必须符合正则：`^[A-Za-z_][A-Za-z0-9_]*$`

### 4.2 关系类型

| 关系类型 | 属性 | 说明 |
|---------|------|------|
| `RELATES_TO` | relation_type, content, triple_id | 实体间的关系 |

### 4.3 典型查询模式

```cypher
// 查询种子实体的子图
MATCH (seed:Entity:MilvusKB:`{kb_id}`)
WHERE seed.entity_id IN $entity_ids
MATCH p = (seed)-[*1..2]-(n:MilvusKB:`{kb_id}`)
WITH p LIMIT $path_limit
RETURN nodes(p) AS nodes, relationships(p) AS edges
```

**设计亮点**：
- **标签隔离**：每个知识库的实体使用独立标签，避免跨库污染
- **关系溯源**：三元组记录原文内容（content），便于验证
- **子图查询**：支持2跳范围内的子图检索

## 五、MinIO 对象存储详解

MinIO 负责存储**文件对象**，包括原始文档和解析后的内容。

### 5.1 Bucket 配置

| Bucket名称 | 用途 | 访问权限 |
|-----------|------|---------|
| `knowledgebases` | 知识库原始文档和解析结果 | 私有 |
| `public` | 公开访问的图片等资源 | 公开读 |

### 5.2 目录结构

```
knowledgebases/
├── {kb_id}/
│   ├── upload/          # 原始上传文件
│   │   └── {filename}_{timestamp}{ext}
│   ├── parsed/          # 解析后的Markdown
│   │   └── {file_id}.md
│   └── chunks/          # 分块结果（可选）
│       └── {file_id}_chunks.json
```

### 5.3 文件命名规则

- **原始文件**：`{basename}_{timestamp}{ext}`（时间戳避免冲突）
- **解析文件**：`{file_id}.md`（使用file_id作为标识）

**设计亮点**：
- **时间戳命名**：避免文件名冲突
- **按知识库隔离**：每个知识库独立目录
- **解析结果持久化**：Markdown格式便于复用

## 六、Redis 存储详解

Redis 用于**缓存、事件流和任务队列**，提供高性能的临时数据存储。

### 6.1 Key 模式

| Key模式 | 数据类型 | 用途 | TTL |
|---------|---------|------|-----|
| `run:{run_id}:status` | STRING | Agent运行状态 | 1小时 |
| `run:{run_id}:events` | STREAM | 运行事件流 | 1小时 |
| `run:{run_id}:cancel` | STRING | 取消信号 | 1小时 |
| `thread:{thread_id}:state` | HASH | 会话状态 | 24小时 |
| `task:{task_id}` | HASH | 任务状态 | 1小时 |
| `user:{uid}:visible_kbs` | STRING(JSON) | 用户可见知识库缓存 | 5分钟 |

### 6.2 事件流结构

```
XADD run:{run_id}:events * \
  event_type "token" \
  content "你好" \
  timestamp "1690000000000"
```

**事件类型**：
- `token`：LLM输出的token
- `tool_call`：工具调用
- `tool_result`：工具结果
- `error`：错误信息
- `complete`：运行完成

### 6.3 任务队列

使用 **ARQ**（Async Redis Queue）实现异步任务：

| 队列名称 | 任务类型 | 说明 |
|---------|---------|------|
| `arq:queue` | `process_agent_run` | Agent运行任务 |
| `arq:queue` | `execute_trigger_run` | 触发器执行任务 |
| `arq:queue` | `scan_triggers` | 定时扫描触发器（cron） |

**设计亮点**：
- **事件流**：支持实时推送LLM输出到前端
- **取消机制**：通过Redis Key实现协作式取消
- **任务队列**：ARQ支持任务重试、超时控制、定时任务

## 七、数据存储协同关系

### 7.1 知识库文档处理链路

```
用户上传文件
    ↓
[MinIO] 存储原始文件
    ↓
[PostgreSQL] 创建 knowledge_files 记录（status=uploaded）
    ↓
[PostgreSQL] 更新 status=parsing
    ↓
[MinIO] 存储解析后的Markdown
    ↓
[PostgreSQL] 创建 knowledge_chunks 记录
    ↓
[Milvus] 写入向量数据（embedding + content）
    ↓
[PostgreSQL] 更新 status=parsed, chunk_count
    ↓
[Neo4j] 写入知识图谱（实体+关系）
    ↓
[PostgreSQL] 更新 knowledge_graph_entities, knowledge_graph_triples
```

### 7.2 Agent对话链路

```
用户发送消息
    ↓
[PostgreSQL] 创建 agent_runs 记录（status=pending）
    ↓
[Redis] XADD 事件流（run:{run_id}:events）
    ↓
[Redis] 设置状态（run:{run_id}:status=running）
    ↓
[LangGraph] 执行Agent逻辑
    ↓
[Milvus] 检索知识库（如果启用）
    ↓
[Neo4j] 图谱增强检索（如果启用）
    ↓
[Redis] 持续写入事件流（token/tool_call等）
    ↓
[PostgreSQL] 创建 messages 记录
    ↓
[PostgreSQL] 更新 agent_runs（status=completed）
    ↓
[Redis] 清理临时Key
```

### 7.3 数据一致性保证

| 场景 | 保证机制 |
|------|---------|
| 文件删除 | PostgreSQL 级联删除 → Milvus 删除向量 → Neo4j 删除实体/关系 |
| 知识库删除 | PostgreSQL 级联删除 → MinIO 删除文件 → Milvus 删除Collection → Neo4j 删除标签 |
| 任务取消 | Redis 设置取消信号 → Worker 检查信号 → 提前终止 |

## 八、性能优化策略

### 8.1 PostgreSQL

- **索引优化**：对高频查询字段建立索引（kb_id, file_id, chunk_id, entity_id）
- **JSON字段**：使用JSONB存储灵活配置，支持部分更新
- **级联删除**：外键约束设置 `ON DELETE CASCADE`，自动清理关联数据

### 8.2 Milvus

- **IVF_FLAT索引**：平衡检索精度和速度
- **内存加载**：Collection创建后自动加载到内存
- **并发控制**：使用信号量限制并发查询数（默认8）

### 8.3 Neo4j

- **标签隔离**：每个知识库独立标签，避免全图扫描
- **子图限制**：查询时限制路径数量（`LIMIT $path_limit`）
- **连接复用**：使用全局共享连接，避免重复创建

### 8.4 Redis

- **TTL自动清理**：所有Key设置过期时间，避免内存泄漏
- **事件流裁剪**：限制事件流长度，避免无限增长
- **批量写入**：ChunkedEventWriter 批量写入事件，减少I/O
