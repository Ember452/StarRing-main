### 2.2 模型缓存优化

**多级缓存架构**（backend/package/starring/models/providers/cache.py）：

```python
import hashlib
from functools import lru_cache
from datetime import timedelta

class ModelCache:
    """三级缓存：内存 -> Redis -> 模型服务"""

    def __init__(self):
        self._memory_cache = {}  # L1: 进程内存
        self._redis_client = redis.Redis()  # L2: Redis
        self._ttl = timedelta(hours=24)

    async def get_model(self, model_spec: str):
        # L1 缓存命中
        if model_spec in self._memory_cache:
            return self._memory_cache[model_spec]

        # L2 缓存命中
        cache_key = f"model:{model_spec}"
        cached = await self._redis_client.get(cache_key)
        if cached:
            model = self._deserialize(cached)
            self._memory_cache[model_spec] = model
            return model

        # L3 调用模型服务
        model = await self._load_model_from_service(model_spec)
        await self._redis_client.setex(cache_key, self._ttl, self._serialize(model))
        self._memory_cache[model_spec] = model
        return model
```

```python
# backend/package/starring/services/run_queue_service.py
class RunQueueService:
    def __init__(self):
        self.redis = redis.Redis()
        self.queue_key = "agent_runs:queue"

    async def enqueue_run(self, run_id: str, priority: int = 0):
        """优先级队列"""
        await self.redis.zadd(
            self.queue_key,
            {run_id: priority}
        )

    async def dequeue_run(self) -> str | None:
        """原子性弹出最高优先级任务"""
        result = await self.redis.zpopmin(self.queue_key)
        if result:
            return result[0][0].decode()
        return None
```

```python
async def parse_large_file(self, file_path: str):
    """流式处理大文件，避免内存溢出"""
    chunk_size = 1024 * 1024  # 1MB
    async with aiofiles.open(file_path, 'rb') as f:
        while chunk := await f.read(chunk_size):
            yield await self.process_chunk(chunk)
```

### 💡 面试问答要点

**Q1: 如何选择异步框架？为什么选FastAPI而不是Django？**

A: FastAPI 原生支持 async/await，基于 Starlette 和 Pydantic，性能接近 Go/Node.js。Django 的同步设计在 I/O 密集场景（数据库、API调用）性能较差。对于 Agent 系统这种大量 LLM API 调用和数据库访问的场景，FastAPI 的异步特性可以将吞吐量提升 3-5 倍（估算）。

**Q2: 三级缓存的设计思路？**

A: 遵循"局部性原理"：
- **L1 内存缓存**：热点数据（95%命中率），访问延迟 <1ms
- **L2 Redis缓存**：共享数据（80%命中率），访问延迟 ~5ms
- **L3 模型服务**：冷数据（首次访问），加载延迟 ~10s

通过 LRU 算法自动淘汰冷数据，避免内存泄漏。

**Q3: 如何优化向量检索性能？**

A: 从三个维度优化：
1. **索引选择**：IVF_FLAT 平衡精度和速度，适合千万级向量
2. **参数调优**：nlist=128, nprobe=16，在召回率和速度间取平衡
3. **元数据过滤**：先过滤再检索，减少候选向量数量

**Q4: 如何监控和定位性能瓶颈？**

A: 建立三层监控体系：
1. **应用层**：Prometheus 记录接口耗时、数据库查询时间
2. **中间件层**：Redis/Milvus/PostgreSQL 自带监控工具
3. **系统层**：Docker stats 监控容器资源使用

通过 Grafana 统一可视化，设置阈值告警。
