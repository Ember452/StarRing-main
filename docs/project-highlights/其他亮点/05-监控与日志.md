### 2.1 访问日志中间件

**实现**（backend/server/utils/access_log_middleware.py）：

```python
class AccessLogMiddleware(BaseHTTPMiddleware):
    """访问日志中间件 - 记录请求处理时间"""

    async def dispatch(self, request: Request, call_next: Callable) -> Response:
        # 记录请求开始时间
        start_time = time.perf_counter()

        # 获取客户端IP
        client_ip = _extract_client_ip(request)

        # 处理请求
        response = await call_next(request)

        # 计算处理时间
        process_time = time.perf_counter() - start_time
        process_time_ms = int(process_time * 1000)  # 转换为毫秒

        # 格式化日志消息
        log_message = (
            f"{client_ip}:{request.client.port if request.client else 'unknown'} - "
            f'"{request.method} {request.url.path}{"?" + request.url.query if request.url.query else ""} '
            f'HTTP/{request.scope["http_version"]}" '
            f"{response.status_code} - {process_time_ms}ms"
        )

        # 记录日志
        self.logger.info(log_message)
        return response
```

**日志输出示例**：

```
2024-01-01 10:30:45 INFO: 192.168.1.100:54321 - "POST /api/chat/messages HTTP/1.1" 200 - 152ms
2024-01-01 10:30:46 INFO: 192.168.1.100:54322 - "GET /api/agents HTTP/1.1" 200 - 23ms
```

**监控指标**：

| 指标 | 提取方式 | 用途 |
|------|---------|------|
| 客户端IP | X-Forwarded-For 或 request.client.host | 安全审计、地域分析 |
| 请求路径 | request.url.path | 接口调用量统计 |
| HTTP方法 | request.method | 资源操作分析 |
| 状态码 | response.status_code | 成功率监控 |
| 处理时间 | time.perf_counter() | 性能分析 |

### 2.3 结构化日志

**日志配置**（backend/server/utils/common_utils.py）：

```python
import logging
import sys

def setup_logging():
    """配置结构化日志"""
    root_logger = logging.getLogger()
    root_logger.setLevel(logging.INFO)

    # 控制台输出
    console_handler = logging.StreamHandler(sys.stdout)
    console_handler.setLevel(logging.INFO)

    # 统一格式
    formatter = logging.Formatter(
        fmt="%(asctime)s %(levelname)s %(name)s: %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S"
    )
    console_handler.setFormatter(formatter)

    root_logger.addHandler(console_handler)

    # 第三方库日志降级
    logging.getLogger("httpx").setLevel(logging.WARNING)
    logging.getLogger("httpcore").setLevel(logging.WARNING)
```

**日志级别使用规范**：

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| DEBUG | 详细调试信息 | "Processing message: {message_id}" |
| INFO | 正常业务流程 | "Agent run created: {run_id}" |
| WARNING | 潜在问题 | "Slow query detected: {duration}ms" |
| ERROR | 错误但可恢复 | "Failed to connect to Milvus, using fallback" |
| CRITICAL | 严重错误 | "Database connection lost" |

### 💡 面试问答要点

**Q1: 为什么选择Langfuse而不是其他可观测性工具？**

A: Langfuse的核心优势：
1. **LLM原生**：专为LLM应用设计，内置Token追踪、Prompt版本管理
2. **开源可控**：支持自托管，数据不出域，满足安全要求
3. **集成简单**：提供Python SDK，几行代码即可集成
4. **成本透明**：可视化的Token用量分析，便于成本控制

**Q2: 如何平衡测试覆盖率和开发效率？**

A: 采用分层策略：
1. **单元测试**：只测核心逻辑，快速反馈（<30s）
2. **集成测试**：覆盖关键接口，真实环境验证（~2min）
3. **E2E测试**：只测核心链路，数量少但价值高（~5min）

不追求100%覆盖率，而是关注核心路径和边界条件。

**Q3: 访问日志中间件如何处理高并发场景？**

A: 通过设计优化：
1. **异步写入**：使用异步日志库，不阻塞请求处理
2. **缓冲批量**：日志先写入内存缓冲区，定期刷盘
3. **结构化输出**：JSON格式便于日志平台解析和聚合
4. **分级存储**：INFO日志保留7天，ERROR保留30天

**Q4: 如何监控Agent运行的质量和成本？**

A: 三层监控：
1. **实时监控**：Langfuse追踪每次运行，实时反馈错误
2. **离线分析**：每日汇总Token用量、成功率、平均耗时
3. **预算控制**：设置每日Token上限，超限自动降级模型
