## 一、技术亮点概览

构建了多层安全防护体系，实现：
- **登录限流**：防止暴力破解，每IP每分钟最多10次尝试
- **CORS严格配置**：生产环境拒绝通配符，明确白名单
- **密码安全存储**：使用Argon2id哈希，防止彩虹表攻击
- **JWT认证**：无状态认证，支持过期和刷新
- **沙盒隔离**：Agent工具执行在独立容器，防止恶意代码

### 2.1 登录限流中间件

**实现**（backend/server/main.py）：

```python
RATE_LIMIT_MAX_ATTEMPTS = 10  # 每分钟最多10次
RATE_LIMIT_WINDOW_SECONDS = 60
RATE_LIMIT_ENDPOINTS = {("/api/auth/token", "POST")}

_login_attempts: defaultdict[str, deque[float]] = defaultdict(deque)
_attempt_lock = asyncio.Lock()  # 异步锁保证线程安全

class LoginRateLimitMiddleware(BaseHTTPMiddleware):
    """登录限流中间件 - 防止暴力破解"""

    async def dispatch(self, request: Request, call_next):
        normalized_path = request.url.path.rstrip("/") or "/"
        request_signature = (normalized_path, request.method.upper())

        if request_signature in RATE_LIMIT_ENDPOINTS:
            client_ip = _extract_client_ip(request)
            now = time.monotonic()

            async with _attempt_lock:
                attempt_history = _login_attempts[client_ip]

                # 清理过期记录
                while attempt_history and now - attempt_history[0] > RATE_LIMIT_WINDOW_SECONDS:
                    attempt_history.popleft()

                # 判断是否超限
                if len(attempt_history) >= RATE_LIMIT_MAX_ATTEMPTS:
                    retry_after = int(max(1, RATE_LIMIT_WINDOW_SECONDS - (now - attempt_history[0])))
                    return JSONResponse(
                        status_code=status.HTTP_429_TOO_MANY_REQUESTS,
                        content={"detail": "登录尝试过于频繁，请稍后再试"},
                        headers={"Retry-After": str(retry_after)},
                    )

                # 记录尝试
                attempt_history.append(now)

            response = await call_next(request)

            # 登录成功则清除记录
            if response.status_code < 400:
                async with _attempt_lock:
                    _login_attempts.pop(client_ip, None)

            return response

        return await call_next(request)
```

**安全策略**：

| 防护措施 | 参数 | 效果 |
|---------|------|------|
| 限流阈值 | 10次/分钟 | 阻止自动化攻击 |
| 时间窗口 | 60秒 | 防止持续攻击 |
| 异步锁 | asyncio.Lock | 保证并发安全 |
| Retry-After | 响应头 | 友好提示重试时间 |

### 2.2 CORS安全配置

**实现**（backend/server/main.py）：

```python
DEFAULT_DEVELOPMENT_CORS_ORIGINS = ("http://localhost:5173", "http://127.0.0.1:5173")
EXPLICIT_CORS_METHODS = ("DELETE", "GET", "HEAD", "OPTIONS", "PATCH", "POST", "PUT")
EXPLICIT_CORS_HEADERS = ("Accept", "Authorization", "Content-Type", "Last-Event-ID", "X-Requested-With")

def _parse_cors_origins() -> list[str]:
    """解析CORS白名单"""
    value = os.getenv("STARRING_CORS_ORIGINS")
    origins = [origin.strip() for origin in (value or "").split(",") if origin.strip()]

    if origins:
        return origins

    environment = (os.getenv("STARRING_ENV") or "development").strip().lower()
    if environment in {"production", "prod"}:
        return []  # 生产环境必须显式配置

    return list(DEFAULT_DEVELOPMENT_CORS_ORIGINS)

def _build_cors_options(origins: list[str] | None = None) -> dict[str, object]:
    """构建CORS配置"""
    allow_origins = _parse_cors_origins() if origins is None else origins

    if "*" in allow_origins:
        # 通配符模式（仅限特殊场景）
        return {
            "allow_origins": ["*"],
            "allow_credentials": False,
            "allow_methods": ["*"],
            "allow_headers": ["*"],
        }

    # 严格白名单模式（推荐）
    return {
        "allow_origins": allow_origins,
        "allow_credentials": True,
        "allow_methods": list(EXPLICIT_CORS_METHODS),
        "allow_headers": list(EXPLICIT_CORS_HEADERS),
        "expose_headers": ["Content-Disposition", "X-Lock-Remaining"],
    }
```

**安全原则**：

| 配置项 | 开发环境 | 生产环境 |
|--------|---------|---------|
| allow_origins | localhost:5173 | 显式域名列表 |
| allow_credentials | True | True（严格模式下） |
| allow_methods | 显式列表 | 显式列表 |
| allow_headers | 显式列表 | 显式列表 |
| 通配符 | 禁用 | 禁用 |

### 2.3 密码安全存储

**实现**（backend/package/starring/utils/auth_utils.py）：

```python
from argon2 import PasswordHasher
from argon2.exceptions import InvalidHash, VerificationError, VerifyMismatchError

PASSWORD_HASHER = PasswordHasher()

class AuthUtils:
    @staticmethod
    def hash_password(password: str) -> str:
        """使用Argon2id哈希密码"""
        return PASSWORD_HASHER.hash(password)

    @staticmethod
    def verify_password(stored_password: str, provided_password: str) -> bool:
        """验证密码（先检查哈希格式再校验）"""
        if not stored_password.startswith("$argon2"):
            return False
        try:
            return PASSWORD_HASHER.verify(stored_password, provided_password)
        except (InvalidHash, VerifyMismatchError, VerificationError):
            return False
```

**安全特性**：

| 特性 | 实现 | 防护对象 |
|------|------|---------|
| 哈希算法 | Argon2id | 彩虹表攻击、GPU暴力破解 |
| 盐值 | 自动生成 | 相同密码反推 |
| 内存硬性 | 可配置内存开销 | GPU/ASIC攻击 |
| 不可逆 | 单向哈希 | 数据库泄露 |

### 2.4 JWT认证机制

**实现**（backend/package/starring/utils/auth_utils.py）：

```python
import jwt
from starring.utils.datetime_utils import utc_now

JWT_ALGORITHM = "HS256"
JWT_EXPIRATION = 7 * 24 * 60 * 60  # 7天
JWT_AUDIENCE = "starring-know-api"

class AuthUtils:
    @staticmethod
    def create_access_token(data: dict[str, Any], expires_delta: timedelta | None = None) -> str:
        """创建JWT Token"""
        to_encode = data.copy()
        expire = utc_now() + (expires_delta or timedelta(seconds=JWT_EXPIRATION))
        to_encode.update({"exp": expire, "iss": _get_jwt_issuer(), "aud": JWT_AUDIENCE})
        return jwt.encode(to_encode, _get_jwt_secret_key(), algorithm=JWT_ALGORITHM)

    @staticmethod
    def verify_access_token(token: str) -> dict[str, Any]:
        """验证JWT Token（过期或无效则抛出异常）"""
        try:
            return jwt.decode(
                token,
                _get_jwt_secret_key(),
                algorithms=[JWT_ALGORITHM],
                issuer=_get_jwt_issuer(),
                audience=JWT_AUDIENCE,
                options={"require": ["exp", "sub", "iss", "aud"]},
            )
        except jwt.ExpiredSignatureError:
            raise ValueError("令牌已过期")
        except jwt.InvalidTokenError:
            raise ValueError("无效的令牌")
```

**Token安全策略**：

| 配置 | 值 | 说明 |
|------|------|------|
| 签名算法 | HS256 | 对称加密，性能好 |
| 过期时间 | 7天 | 平衡安全与体验 |
| 密钥管理 | 环境变量+自动生成 | 生产环境必须配置 |
| 签发者校验 | iss + aud | 防止令牌跨实例复用 |

### 💡 面试问答要点

**Q1: 为什么选择Argon2id而不是MD5或SHA256？**

A: Argon2id的核心优势：
1. **内存硬性设计**：通过内存开销增加攻击成本，抵御GPU/ASIC暴力破解
2. **内置盐值**：自动生成盐值，防止彩虹表攻击
3. **适应性**：可调整内存、迭代次数、并行度应对硬件性能提升
4. **专业认可**：Password Hashing Competition获胜者，OWASP推荐

MD5和SHA256设计目标是快速计算，适合数据校验但不适合密码存储。bcrypt虽然也适合密码存储，但Argon2id对GPU攻击的抵抗力更强。

**Q2: 登录限流中间件如何处理分布式部署场景？**

A: 当前方案适合单机或小规模集群：
- **单机内存方案**：使用进程内字典 + 异步锁，性能好但无法跨实例共享
- **分布式扩展**：可改用Redis记录尝试次数，利用Redis的原子操作和TTL

生产环境建议使用Redis方案，支持多实例部署。

**Q3: CORS配置中为什么不推荐使用通配符？**

A: 通配符 `*` 的安全风险：
1. **信息泄露**：允许任意域名发起请求，可能泄露敏感数据
2. **CSRF攻击**：恶意网站可以伪造用户请求
3. **凭证暴露**：通配符模式下必须禁用 `allow_credentials`

生产环境应该明确列出允许的域名，减少攻击面。

**Q4: 沙盒隔离的核心价值是什么？**

A: 核心价值在于限制Agent工具执行的影响范围：
1. **代码隔离**：用户上传的Python代码在沙盒中执行，无法访问宿主机敏感资源
2. **资源隔离**：限制CPU和内存使用，防止资源耗尽
3. **网络隔离**：沙盒网络与内网隔离，防止横向渗透
4. **文件隔离**：虚拟路径映射，用户只能访问自己的数据目录

这解决了Agent应用中"执行用户提供的代码"这一最大的安全隐患。
