# StarRing 系统全景图

> 零基础入门文档 —— 帮助新人在 30 分钟内建立对 StarRing 全貌的认知

## 1. 一句话介绍

**StarRing** 是基于大模型的智能知识库与知识图谱智能体开发平台，融合 RAG 技术与知识图谱技术，基于 **LangGraph v1 + Vue.js + FastAPI** 架构构建，自研知识图谱能力（Neo4j + Milvus + PostgreSQL 三存储协同），完全通过 Docker Compose 管理。

## 3. 核心数据流（端到端）

### 数据流 1：用户上传文档

```mermaid
sequenceDiagram
    participant U as 用户
    participant API as FastAPI (api-dev)
    participant MinIO as MinIO
    participant Parser as 文档解析器<br/>(MinerU/PaddleX/RapidOCR)
    participant Chunk as 切割引擎<br/>(6种策略)
    participant EMB as Embedding (bge-m3)
    participant Milvus as Milvus
    participant Neo4j as Neo4j
    participant PG as PostgreSQL

    U->>API: POST /api/knowledge/files/upload
    API->>MinIO: 存储原始文件
    API->>PG: 写入文件记录 (status=pending)
    API-->>U: 返回 file_id

    U->>API: POST /api/knowledge/files/parse
    API->>Parser: 调用解析引擎 (MinerU/PaddleX)
    Parser-->>API: 返回 Markdown 内容
    API->>PG: 更新文件状态 (status=parsed)

    U->>API: POST /api/knowledge/files/index
    API->>Chunk: 按策略切割 Markdown<br/>(通用/书籍/法律/QA/语义/分隔符)
    Chunk-->>API: 返回 chunks[]
    API->>EMB: 批量 Embedding (bge-m3)
    API->>Milvus: 插入向量 + BM25稀疏索引
    API->>PG: 写入 chunk 记录

    Note over API,Neo4j: 可选：图谱构建
    API->>Neo4j: LLM 抽取实体/关系 → MERGE 写入图谱
    API->>Milvus: 实体/三元组向量入库
    API->>PG: 更新 graph_indexed=true
```

### 数据流 2：用户对话检索

```mermaid
sequenceDiagram
    participant U as 用户
    participant API as FastAPI (api-dev)
    participant Agent as LangGraph Agent
    participant MW as 知识库中间件
    participant Milvus as Milvus
    participant Neo4j as Neo4j
    participant LLM as LLM
    participant Redis as Redis

    U->>API: POST /api/chat (SSE)
    API->>Redis: 入队 Agent Run
    API-->>U: SSE 连接建立

    Note over Redis,Agent: ARQ Worker 消费
    Redis->>Agent: 执行 LangGraph

    Agent->>MW: 挂载知识库工具
    MW->>Milvus: 向量检索 (COSINE top_k)
    MW->>Milvus: BM25 全文检索
    MW->>Neo4j: 图检索 (PPR 多跳扩散)

    Note over MW: RRF 融合排序
    MW-->>Agent: 检索结果 (chunks + graph context)

    opt Re-Rank
        Agent->>LLM: 重排序 (可选)
    end

    Agent->>LLM: 生成回答 (streaming)
    LLM-->>Agent: token 流式返回
    Agent->>Redis: 写入事件流
    Redis-->>U: SSE 推送
```

### 数据流 3：Agent 异步执行

```mermaid
sequenceDiagram
    participant U as 用户
    participant API as FastAPI (api-dev)
    participant ARQ as ARQ 队列 (Redis)
    participant Worker as ARQ Worker
    participant LG as LangGraph
    participant CP as Checkpointer<br/>(PostgreSQL)
    participant Redis as Redis Stream
    participant SSE as SSE 推送

    U->>API: 发起对话 / 恢复对话
    API->>ARQ: enqueue run_task
    API-->>U: 返回 run_id

    ARQ->>Worker: 消费任务
    Worker->>LG: 创建/恢复 LangGraph 执行

    loop 每个 LangGraph step
        LG->>CP: 持久化 checkpoint
        LG->>Redis: 写入事件 (token/tool/status)
        Redis->>SSE: 推送到前端
    end

    LG-->>Worker: 执行完成
    Worker->>CP: 更新最终状态
    Worker->>Redis: 写入完成事件
    Redis->>SSE: 最终推送
```

## 4. 模块依赖关系

```mermaid
graph LR
    subgraph server["server (HTTP 适配层)"]
        routers[routers]
        utils[utils]
    end

    subgraph pkg["StarRing (业务包)"]
        agents[agents]
        services[services]
        repos[repositories]
        knowledge[knowledge]
        models[models]
        storage[storage]
        config[config]
    end

    routers --> services
    routers --> repos
    utils --> config

    agents --> services
    agents --> knowledge
    agents --> models

    services --> repos
    services --> knowledge
    services --> models
    services --> storage
    services --> agents

    knowledge --> models
    knowledge --> storage
    knowledge --> repos

    repos --> storage

    storage --> config
```

**依赖规则**：

- `routers` 只做请求解析与响应装配，业务逻辑委托 `services`
- `services` 串联 `repositories`、`agents`、`knowledge`，是用例层
- `repositories` 是数据库访问边界，不引用 `agents` 或 `knowledge`
- `knowledge` 是知识库领域，依赖 `models`（Embedding/LLM）和 `storage`（Milvus/Neo4j）
- `agents` 依赖 `knowledge`（检索工具）和 `services`（运行管理）

## 6. 技术栈一览表

| 层级 | 技术 | 说明 |
|------|------|------|
| **HTTP 层** | FastAPI + Uvicorn | 异步 Web 框架，Pydantic 校验，SSE 流式响应 |
| | ARQ (Redis) | 异步任务队列，Agent Run 的消费者 |
| | Pydantic v2 | 请求/响应模型校验 |
| **Agent 层** | LangGraph v1 | 智能体执行引擎，支持状态图、Checkpoint |
| | langchain-core | 工具/模型抽象层 |
| | langchain-openai / langchain-deepseek | 模型 Provider 适配 |
| | langchain-mcp-adapters | MCP 协议适配 |
| **检索层** | pymilvus | 向量检索 + BM25 稀疏检索 + 混合检索 (RRF) |
| | neo4j (Python Driver) | 知识图谱存储与 Cypher 查询 |
| | igraph | Personalized PageRank 图检索排序 |
| | bge-m3 (Embedding) | 多语言 Embedding 模型，支持稠密+稀疏+多向量 |
| **存储层** | PostgreSQL 16 + SQLAlchemy 2.0 | 业务元数据、知识库元数据、LangGraph Checkpoint |
| | asyncpg | PostgreSQL 异步驱动 |
| | Redis 7 | 运行事件流、取消信号、ARQ 任务队列 |
| | MinIO | 对象存储（文件、图片、Milvus 后端存储） |
| **文档处理** | MinerU | GPU 加速文档解析（PDF/图片→Markdown） |
| | PaddleX | GPU 加速 OCR |
| | RapidOCR / DeepSeek OCR | CPU 备选 OCR 方案 |
| | RAGFlow-like Chunking | 6 种分块策略（通用/书籍/法律/QA/语义/分隔符） |
| **前端** | Vue 3 + Vite | SPA 前端，Pinia 状态管理 |
| | pnpm | 包管理 |
| | Less | CSS 预处理 |
| **基础设施** | Docker Compose | 开发/部署编排，热重载 |
| | Langfuse | LLM 可观测性（可选） |
| | Sandbox Provisioner | Agent 工具执行沙盒隔离 |

## 7. 新手快速上手

### 环境要求

| 依赖 | 最低版本 | 说明 |
|------|----------|------|
| Docker | 24+ | 容器运行时 |
| Docker Compose | v2+ | 服务编排 |
| Git | 2.x | 代码管理 |

> 如需启用 MinerU / PaddleX 文档解析（`profile: all`），还需要 NVIDIA GPU + nvidia-container-toolkit。

### 一键启动

```bash
# 1. 克隆项目
git clone <repo-url> && cd starRing-main-be

# 2. 复制环境配置（首次部署会自动生成 JWT 密钥和管理员账号）
cp .env.example .env   # 如已有 .env 可跳过

# 3. 构建并启动所有服务
docker compose up -d

# 4. （可选）启用 GPU 文档解析服务
docker compose --profile all up -d
```

### 验证服务

```bash
# 检查所有容器是否运行
docker ps

# 验证 API 健康检查
curl http://localhost:5050/api/system/health

# 查看后端日志
docker logs api-dev --tail 50

# 查看前端日志
docker logs web-dev --tail 50

# 查看 Worker 日志
docker logs worker-dev --tail 50
```

服务就绪后：

- **前端**：访问 http://localhost:5173
- **API 文档**：访问 http://localhost:5050/docs (Swagger UI)
- **Neo4j Browser**：访问 http://localhost:7474

### 核心配置说明

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| API 端口 | — | 5050 | docker-compose 中固定 |
| 前端端口 | — | 5173 | Vite dev server |
| PostgreSQL | `POSTGRES_URL` | `postgresql+asyncpg://postgres:postgres@postgres:5432/starring` | 业务数据库 |
| Redis | `REDIS_URL` | `redis://redis:6379/0` | 事件流与队列 |
| Neo4j | `NEO4J_URI` | `bolt://graph:7687` | 知识图谱 |
| Milvus | `MILVUS_URI` | `http://milvus:19530` | 向量检索 |
| MinIO | `MINIO_URI` | `http://minio:9000` | 对象存储 |
| JWT 密钥 | `JWT_SECRET_KEY` | 自动生成 | 首次部署留空即可 |
| 精简模式 | `LITE_MODE` | `false` | 为 `true` 时跳过知识库/图谱/评估等重依赖 |
| MinerU API | `MINERU_API_URI` | `http://mineru-api:30001` | GPU 文档解析 |
| PaddleX | `PADDLEX_URI` | `http://paddlex:8080` | GPU OCR |

> **热重载**：`api-dev` 和 `web-dev` 挂载了源码目录，修改代码后服务自动更新，无需重启容器。
