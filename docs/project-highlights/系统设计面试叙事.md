# 系统设计面试叙事（45 分钟备考卡 / Cheat Sheet）

> 适用场景：大厂「系统设计 + 项目深挖」轮。本文把 `项目简历写法/01~08` 的 8 大亮点串成一份**可照着讲的剧本**，既给你开场话术，也给你每个模块的「深挖索引」与「防露怯清单」。
> 配套文档：`系统全景图.md`、`README.md`、各篇 `权衡与失效模式` 与 `指标说明` 小节。
> 原则：**先讲清楚 WHY 和 TRADEOFF，再讲 HOW；所有数字要么能复现，要么明确标「估算/设计预期」**。

---

## 0. 一句话定位（开场 30 秒，背下来）

> 「我主导设计了一个**基于大模型的智能知识库 + 知识图谱智能体平台 StarRing**：用 LangGraph 编排多 Agent，融合向量/BM25/图检索的 RAG，配套异步流式 API、状态持久化、上下文压缩、工具沙盒与异步任务队列，目标是让 Agent 在长任务、多工具、大知识库下**可靠、可恢复、成本可控**地跑生产。」

这一句话同时抛出 4 个面试官会追的钩子：**可靠（状态/取消）、可恢复（Checkpointer/断线）、成本可控（压缩/批处理）、安全（沙盒）**。

---

## 1. 需求澄清追问（别急着画架构，先反问 2 分钟）

把「需求澄清」当成展示成熟度的机会，按优先级问：

| 维度 | 关键追问 | 你想引导到的设计点 |
|------|----------|-------------------|
| 规模 | 知识库体量？QPS？单对话平均轮次？ | 决定 Milvus 分片、并发信号量=8、图 `max_nodes` |
| 可靠性 | 长任务允许中断吗？用户要能取消吗？ | Checkpointer + 中断恢复 + 协作式取消 |
| 成本 | Token 成本上限？上下文窗口？ | 摘要压缩（100K 触发）、批处理降 I/O |
| 安全 | 工具能执行什么？是否需要隔离？ | 三层沙盒（路径/文件/容器） |
| 时延 | TTFT 要求？流式还是整块？ | SSE + Redis Stream 断线重连 |
| 多租户 | 数据是否隔离？合规要求？ | 知识库工厂按 kb 隔离、沙盒虚拟路径 |

> 话术：「在动手前我想先确认规模和可靠性目标，因为**并发限制、状态后端、压缩阈值**这些参数都直接由它们决定。」——这一句就把你从「背八股」拉到「权衡设计」。

## 2. 核心架构演进与关键选型（主线，约 12 分钟）

### 2.1 整体分层（对着 `系统全景图.md` 讲）

```
用户(Vue) → FastAPI(SSE) → ARQ Worker → LangGraph Agent
                                  │
        ┌─────────────────────────┼─────────────────────────┐
        ▼                         ▼                         ▼
   中间件栈(10层)            知识库管理层             工具沙盒(Provisioner)
        │                         │                         │
        ▼                         ▼                         ▼
   检索(向量+BM25+图)      Milvus/Neo4j/PG        Docker/K8s 容器
        │
        ▼
   Redis Stream(事件/队列/取消)
```

- **请求层**：FastAPI + SSE 流式；长任务入 ARQ 队列，worker 异步消费。
- **智能体层**：LangGraph StateGraph，10 层中间件（文件系统→附件→知识库→Skills→子智能体→摘要→Todo→修补→重试→计量）。
- **检索层**：Milvus（稠密+BM25 稀疏+混合）、Neo4j（图谱）、igraph 做 PPR。
- **存储层**：PostgreSQL（元数据+Checkpoint）、Neo4j、Milvus、Redis（事件流/队列）、MinIO（对象）。

### 2.2 关键选型决策表（面试最爱追问「为什么不用 X」）

| 选型 | 我们的决定 | 主流替代 | 选它的原因（一句话） | 付出的代价 |
|------|-----------|----------|---------------------|------------|
| Agent 编排 | LangGraph v1 | 自研状态机 / CrewAI | 内置 Checkpointer + interrupt/resume，省去自研持久化 | 绑定 v1 schema、图编译开销 |
| 检索融合 | RRF（默认）+ 可选 Re-Ranker | 纯训练 reranker | RRF 零训练、可解释、冷热一致；reranker 作可选增强 | RRF 不补单路召回质量 |
| 向量库 | Milvus | pgvector / Qdrant | 同库支持稠密+BM25 稀疏+混合检索 | 运维稍重 |
| 图库 | Neo4j | 内存图 / pgvector 图 | 持久化 + Cypher 2-hop 子图成熟 | 额外组件 |
| 流式传输 | SSE + Redis Stream | WebSocket / 轮询 | 单向推 token、原生重连、跨进程解耦 | 代理 idle 截断需处理 |
| 任务队列 | ARQ + Redis | Celery / Kafka | 已用 Redis、原生 async、够用 | 超大规模不如 Kafka |
| 取消机制 | 协作式取消 | 强制 kill | 保证状态机一致、清理执行完 | 延迟受轮询间隔约束 |
| 上下文 | 结构化摘要压缩 | 滑窗截断 / 全保留 | 保留语义、避免超限、成本低 | 摘要可能丢信息 |
| 沙盒 | Provisioner(Docker/K8s) | 进程内 exec / 微 VM | 平衡隔离/启动/可移植 | Docker 端安全配置弱于 K8s |
| 知识库 | 工厂+策略(热插拔) | 硬编码 if/elif | 新增类型只实现接口+注册 | 跨类型能力差异靠兼容分支 |

> 讲法：每讲一个选型，先说**解决什么问题**，再说**为什么不是替代方案**，最后承认**代价**——这三者齐了，面试官基本不会再打压。

## 3. 八大亮点深挖索引（链回各篇，约 18 分钟）

> 每篇给：定位 → 必背 3 点 → 可被追问 → 对应文档。按顺序讲，面试官挑哪篇你都能接。

### 01 · 多 Agent 系统架构设计
- **定位**：LangGraph 编排 3 种模式（Orchestrator-Worker / Supervisor / Workflow）+ 10 层中间件。
- **必背**：① 3 种编排模式适用场景；② 中间件顺序耦合（摘要必须在计量前）；③ 多后端 Checkpointer。
- **会被追问**：为什么不用自研状态机？（答：省去持久化/interrupt 自研成本）7 类 Agent 怎么来的？（⚠️ 诚实说：代码有 4 个 buildin 家族 + 动态子智能体，「7」是含动态子智能体的设计口径，建议简历改「4 类内置 + 动态子智能体」）
- 详见：`项目简历写法/01-多Agent系统架构设计.md` 的「权衡与失效模式」「指标说明」。

### 02 · RAG + 知识图谱融合架构
- **定位**：向量 + BM25 + 图三路召回，RRF 融合，PPR 做图扩散。
- **必背**：① RRF 是默认融合、Re-Ranker 是可选增强（二者并存，不是二选一）；② PPR `damping=0.85`、`graph_max_nodes=10000` 子图；③ 图检索异常 `return []` 优雅降级。
- **会被追问**：RRF vs reranker？（见上）召回率 +25% 怎么测的？（⚠️ 诚实说：设计估算，需 golden set 评测，简历标「估算」）PPR 大图谱尾部延迟？（冷启动/大图是失效点）
- 详见：`02-RAG+知识图谱融合架构.md`。

### 03 · 高性能异步 API 设计
- **定位**：SSE 流式 + Redis Stream 断线重连 + 信号量限流（Milvus IO=8）。
- **必背**：① SSE 单向推、原生重连；② Redis Stream 游标 `after_seq` 续传 + TTL；③ `pool_size=10/max_overflow=20` 连接池。
- **会被追问**：SSE vs WebSocket？（单向场景 SSE 更简、穿透 LB 易）TTFT 200-400ms 稳定吗？（⚠️ 区间估算，受模型/网络影响）重连 100% 成功率？（设计目标，缺 chaos 实测）
- 详见：`03-高性能异步API设计.md`。

### 04 · Agent 状态持久化方案
- **定位**：多后端 Checkpointer（PG/SQLite/Memory）+ 中断恢复。
- **必背**：① `_get_checkpointer` 按环境变量切换；② 仅 `interrupted` run 可 resume（否则 409）；③ langgraph 专用池 `autocommit=True`。
- **会被追问**：并发恢复竞争？（run 层守卫兜底，非 checkpoint 层）InMemory 回退？（⚠️ 生产陷阱：sqlite 失败默认回退内存会丢状态，应 `ALLOW_INMEMORY_CHECKPOINTER_FALLBACK=false`）恢复成功率 100%？（设计目标，缺回归）
- 详见：`04-Agent状态持久化方案.md`。

### 05 · 生产级知识库管理系统
- **定位**：工厂 + 策略模式，Milvus/Dify/Notion 热插拔。
- **必背**：① `KnowledgeBaseFactory.register/create`；② 抽象基类 10 个抽象方法（⚠️ 原文档误写 4，实际为 10）；③ `manager` 启动校验 `kb_types_in_use`。
- **会被追问**：为什么不用硬编码？（改代码/需发版）新增类型要多久？（简单 <1 天，复杂自托管按周）跨类型能力差异？（靠兼容分支，长期应抽 capability 标志）
- 详见：`05-生产级知识库管理系统.md`（注意其中的「4→10 抽象方法」更正：原文档误写 4，代码实际为 10 处 `@abstractmethod`）。

### 06 · 长上下文管理方案
- **定位**：结构化摘要压缩（100K 触发、保留 10 条）+ Token 近似计量（±10%）。
- **必背**：① 结构化 Prompt 5 维度（意图/偏好/进度/产物/待办）；② 工具结果落盘只留路径+500 token 预览；③ 阈值/保留数 admin 可配。
- **会被追问**：摘要丢信息怎么办？（结构化保关键维度 + 保留近 10 条）压缩率 70-85% 实测吗？（⚠️ 估算，需评测）100K 阈值余量？（接近 128K 窗口，应动态算）
- 详见：`06-长上下文管理方案.md`。

### 07 · 沙盒环境安全隔离
- **定位**：Provisioner（Docker/K8s）+ 三层隔离（路径/文件/容器）。
- **必背**：① `_READABLE_ROOTS`/`_WRITABLE_ROOTS` 白名单 + `_normalize_path` 防 `..`；② 容器只挂 thread 目录，宿主机不可见（纵深防御）；③ K8s 端 `securityContext` 降权。
- **会被追问**：容器逃逸？（Docker 端 `run_kwargs` 未显式 cap-drop，弱于 K8s 端，已知局限）冷启动？（<2s 是估算，高并发有创建风暴）视觉模型误判？（未知默认放行保兼容）
- ⚠️ **代码路径更正**：实现在 `agents/backends/sandbox/`，非旧文档写的 `tools/provisioner/`。
- 详见：`07-沙盒环境安全隔离.md`。

### 08 · 异步任务队列设计
- **定位**：ARQ + Redis，协作式取消（轮询 200ms）+ ChunkedEventWriter 批处理。
- **必背**：① 双通道取消（Pub/Sub + Redis key + TTL 兜底）；② `ChunkedEventWriter` 100ms/512char 双触发、关键事件立即 flush；③ 区分 Retryable/NonRetryable。
- **会被追问**：协作式 vs 强制 kill？（状态一致）取消延迟 <200ms 稳定吗？（⚠️ 最坏上界，真实取决于 chunk 间隙）90% I/O 减少？（估算，缺基准）
- 详见：`08-异步任务队列设计.md`。

## 4. 容量 / 扩展性 / 成本讨论（约 6 分钟，面试官压轴）

主动抛这块，显示你能从「功能」上升到「系统工程」：

- **容量**：Milvus IO 并发信号量=8 是单 worker 内的硬限；横向扩展靠多 worker 消费同一 ARQ 队列。Redis Stream `maxlen` 近似裁剪控内存，TTL 2h 自动回收。
- **扩展性瓶颈**：① 图谱 PPR 在大 `max_nodes` 下尾部延迟（应加 p99 监控 + 自适应 `max_nodes`）；② 沙盒冷启动在创建风暴下成瓶颈（连接池/心跳缓解）；③ Checkpoint 体积随历史膨胀（靠 06 压缩间接缓解）。
- **成本**：上下文压缩（设计预期 60-75% 降本）+ ChunkedEventWriter 降 Redis I/O（90% 估算）+ 模型预热压 TTFT。讲成本时**务必区分「设计预期」与「实测」**。
- **多租户/隔离**：知识库按 `kb_id` 隔离；沙盒虚拟路径按 uid/thread 隔离；Checkpoint 按 thread 隔离。
- **可观测性**：事件流 schema_version 兼容、TTL、取消信号 TTL；建议补 checkpoint 体积、PPR p99、压缩率实测埋点。

> 话术：「这套系统在功能闭环后，真正的扩展瓶颈在**图谱 PPR 尾部延迟**和**沙盒冷启动**两处，我们已经用信号量/批处理/心跳兜住常见场景，但上线高频图检索时我会优先加这两处的 p99 监控。」——把「已知局限」主动讲出来，反而是加分项。

## 5. 最可能被深挖的坑与作答要点（Top 10 防露怯）

1. **「召回率 +25% / 准确率 +18%」怎么来的？** → 设计估算，无端到端评测；诚实说已规划 golden set 评测脚本。
2. **「状态恢复成功率 100%」有数据吗？** → 设计目标，由 Checkpointer + resume 守卫保证；已规划 kill-worker 回归，目前缺量化。
3. **「压缩率 70-85% / 降本 60-75%」实测吗？** → 设计预期，需压缩前后下游任务质量评测。
4. **「7 类 Agent」对应哪些代码？** → 代码只有 4 个 buildin 家族 + 动态子智能体；改口「4 类内置 + 动态」。
5. **「KB 4 个抽象方法」？** → ❌ 笔误，代码是 10 个 `@abstractmethod`（⚠️ 原文档误写 4，实际为 10）。
6. **「取消延迟 <200ms」是稳定值吗？** → 最坏情况上界（轮询 0.2s），真实取决于 chunk 间隙。
7. **「容器启动 <2s / 资源利用率 +60%」？** → 估算，缺基准；「日均 1000+/稳定 6 个月」无独立来源。
8. **沙盒代码路径？** → `agents/backends/sandbox/`，旧文档 `tools/provisioner/` 已更正。
9. **RRF 和 Re-Ranker 冲突吗？** → 不冲突，RRF 是默认融合，reranker 是可选增强（代码里 `use_reranker` 开关）。
10. **InMemory Checkpointer 回退？** → 生产陷阱，应 `ALLOW_INMEMORY_CHECKPOINTER_FALLBACK=false` 强制 fail-fast。

> 通用应对公式：**「这个数字我们的口径是 X（实测/估算/设计目标），复现方法是 Y；如果现在要上生产，我会先补 Z 的实测。」** 一句话同时展现诚实、方法论与工程闭环。

## 8. 端到端走查（把 8 大亮点串成一次真实请求）

> 用「用户问一个需要查知识库 + 跑工具的长问题」把模块串起来，面试官最爱让你「从头到尾讲一遍」。

```
① 用户发问 ──▶ FastAPI 收请求，enqueue 到 ARQ（08 任务队列）
       │
② ARQ Worker 消费 ──▶ LangGraph 编译图，挂 10 层中间件（01 多Agent）
       │
③ 知识库中间件触发检索 ──▶ 向量+BM25+图三路 → RRF 融合（02 RAG+图谱）
       │                         └─ 图检索异常则 return [] 降级
④ 工具调用（如写代码）──▶ 经沙盒 Provisioner 起容器，三层隔离执行（07 沙盒）
       │
⑤ 上下文增长 ──▶ 超 100K 触发结构化摘要压缩，保留近 10 条（06 长上下文）
       │
⑥ 每一步 checkpoint 落 PG；每 token 经 ChunkedEventWriter 攒批写 Redis Stream（04 状态 / 08 队列）
       │
⑦ SSE 从 Redis Stream 拉事件推前端；断线带 last_seq 重连（03 异步API）
       │
⑧ 用户点取消 ──▶ 双通道取消信号 → 下次 chunk 间隙 raise CancelledError → 标 terminal（08）
       │
⑨ 若 Worker 崩溃 ──▶ 用户 resume，仅 interrupted 可恢复，从 Checkpoint 续跑（04）
```

讲这段时，每跳到一个编号就点一下对应的「亮点编号 + 一句 WHY」。这一遍走完，8 篇就自然连成一张网，而不是 8 个孤立知识点。

## 9. 追问情景模拟（Q → A 范例，照着练）

**Q：你这个 RAG 为什么不直接上 reranker，要用 RRF？**
> A：我们**两者都有**。RRF 是默认融合层，零训练、冷热启动一致、可解释，先把向量/BM25/图三路排好；reranker（cross-encoder）是可选开关 `use_reranker`，在融合结果上做 top-N 精排。选 RRF 作底座是成本和稳定性考量，reranker 只在质量要求高的场景开启，而且它异常时会回退到向量分，不影响主链路。

**Q：用户取消了，你保证状态不丢吗？**
> A：用协作式取消——取消信号走 Pub/Sub + Redis key 双通道，worker 在每次 chunk 间隙检查，触发后把 run 标成 `cancelled` 并清信号，保证清理逻辑跑完、Checkpointer 已落盘。代价是取消延迟有上界（轮询 0.2s + 当前步间隙），不是硬实时。如果 worker 崩了，用户能从 `interrupted` 状态 resume，从 PG checkpoint 续跑。

**Q：长对话成本怎么控？**
> A：两层。一是上下文压缩，超 100K 触发结构化摘要（保留意图/偏好/进度/产物/待办），设计预期降本 60-75%，这是估算、需评测；二是事件流批处理，ChunkedEventWriter 把每 token 写 Redis 攒成 100ms/512char 一批，Redis I/O 降约 90%，也是估算。两者都是「设计预期」，我会在简历里明确标出来，不会当实测讲。

**Q：工具能执行任意代码，安全怎么保证？**
> A：三层——路径白名单（`_READABLE_ROOTS` 只放用户数据+skills，拒绝 `..` 遍历）、文件系统隔离（虚拟路径映射到按 uid/thread 挂的目录，宿主机不可见）、容器级隔离（Docker/K8s，K8s 端 `securityContext` 降权）。纵深防御，任一层漏了还有下一层兜底。已知 Docker 端安全配置比 K8s 端弱，这是我们后续要补的。

## 10. 从 MVP 到生产的演进叙事（讲「为什么长成这样」）

面试官常问「如果重来你会怎么改」，提前准备一条演进线：

1. **MVP 期**：单 Agent + 单向量检索 + 内存队列。最快验证「能对话」。
2. **可靠期**：引入 LangGraph Checkpointer（04）+ ARQ 异步（08），解决「长任务别丢、能取消」。
3. **质量期**：三路检索 + RRF + 图谱（02）+ 知识库工厂（05），解决「答得准、接得多」。
4. **成本/安全期**：上下文压缩（06）+ 沙盒隔离（07）+ SSE/Redis Stream（03），解决「跑得起、跑得安全」。
5. **生产化期**：指标诚信治理、pitfall 文档、监控埋点——也就是你现在看到的这套文档。

> 话术：「架构不是一次设计完的，是跟着可靠性→质量→成本→安全→可观测这条主线长出来的。每个阶段解决一类痛点，所以你看到的中间件、检索路、隔离层都是**被问题逼出来的**，不是过度设计。」
